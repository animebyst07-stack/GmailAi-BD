НАЗНАЧЕНИЕ
----------
Умная база данных для хранения и управления Gmail-аккаунтами.
ИИ-агент анализирует сырой неструктурированный текст и автоматически
заносит аккаунты в SQLite базу данных.

СТЭК
----
- Backend:  Python 3.10+ / Flask 3.x
- БД:       SQLite (встроенная, без внешних серверов)
- Frontend: HTML5 + Vanilla JS + CSS3 (без зависимостей NPM)
- ИИ:       Внешний API (настраивается пользователем: ключ, endpoint, модель)
- Запуск:   python gmailai.py

СТРУКТУРА БАЗЫ ДАННЫХ (SQLite)
-------------------------------
Таблица: accounts
  id              INTEGER PRIMARY KEY AUTOINCREMENT
  email           TEXT NOT NULL
  password        TEXT NOT NULL
  status          TEXT DEFAULT 'active'   -- active / sold / appeal / banned / unknown
  two_factor_code TEXT                    -- TOTP код (если есть)
  recovery_email  TEXT                    -- резервная почта
  recovery_phone  TEXT                    -- резервный телефон
  notes           TEXT                    -- произвольные заметки
  tags            TEXT                    -- JSON-массив тегов
  created_at      DATETIME DEFAULT CURRENT_TIMESTAMP
  updated_at      DATETIME DEFAULT CURRENT_TIMESTAMP

Таблица: chat_history
  id              INTEGER PRIMARY KEY AUTOINCREMENT
  role            TEXT                    -- 'user' или 'assistant'
  content         TEXT                    -- текст сообщения
  actions_count   INTEGER DEFAULT 0       -- кол-во выполненных действий
  created_at      DATETIME DEFAULT CURRENT_TIMESTAMP

Таблица: settings
  id              INTEGER PRIMARY KEY DEFAULT 1
  api_key         TEXT DEFAULT ''
  api_endpoint    TEXT DEFAULT 'https://api.openai.com/v1/chat/completions'
  ai_model        TEXT DEFAULT 'gpt-4o-mini'
  system_prompt   TEXT

Таблица: activity_log
  id              INTEGER PRIMARY KEY AUTOINCREMENT
  type            TEXT                    -- ADD / UPDATE / DELETE / PARSE
  description     TEXT
  created_at      DATETIME DEFAULT CURRENT_TIMESTAMP

ЛОГИКА ИИ-АГЕНТА (МНОГОЭТАПНОСТЬ)
------------------------------------
Шаг 1 — Пользователь кидает сырой текст в чат
Шаг 2 — Backend отправляет текст ИИ с системным промптом
Шаг 3 — ИИ анализирует текст и возвращает JSON с командами:

  {
    "message": "Нашёл 3 аккаунта...",
    "actions": [
      {
        "type": "ADD_ACCOUNT",
        "data": {
          "email": "user@gmail.com",
          "password": "Pass123",
          "status": "active",
          "two_factor_code": "ABC123",
          "recovery_email": null,
          "notes": "куплен 10.01.2025"
        }
      },
      {
        "type": "UPDATE_ACCOUNT",
        "id": 5,
        "data": { "status": "sold" }
      },
      {
        "type": "DELETE_ACCOUNT",
        "id": 7
      },
      {
        "type": "QUERY",
        "message": "Нашёл 15 аккаунтов со статусом 'appeal'"
      }
    ]
  }

Шаг 4 — Backend выполняет каждое действие в SQLite
Шаг 5 — Frontend реактивно обновляет таблицу (WebSocket или polling)
Шаг 6 — Ответ ИИ показывается в чате с иконками действий

ФОРМАТЫ ПАРСИНГА (примеры входных данных)
------------------------------------------
Формат 1: email:password
  test@gmail.com:MyPass123

Формат 2: email|password
  test@gmail.com|MyPass123

Формат 3: Слитный (email имя совпадает с частью пароля)
  Tupa83_9 → email: tupa83@gmail.com, password: Tupa83_9

Формат 4: Многострочный с метками
  Почта: user@gmail.com
  Пароль: qwerty123
  2FA: JBSWY3DPEHPK3PXP
  Статус: продан

Статусы (распознаются по ключевым словам):
  active  → ok, ок, active, рабочий, работает, good
  sold    → продан, sold, продали, куплен
  appeal  → аппеляция, appeal, апелляция, заблок
  banned  → бан, banned, забанен, dead

  4. Настройки    — API ключ, модель, системный промпт

API ENDPOINTS
--------------
GET  /api/accounts           — список с фильтрами
POST /api/accounts           — создать
PATCH /api/accounts/:id      — обновить
DELETE /api/accounts/:id     — удалить
POST /api/accounts/bulk      — массовое создание
POST /api/accounts/bulk-delete — массовое удаление

POST /api/chat               — отправить сообщение агенту
GET  /api/chat/history       — история чата
DELETE /api/chat/history     — очистить историю

GET  /api/settings           — получить настройки
PUT  /api/settings           — обновить настройки

GET  /api/dashboard/stats    — статистика
GET  /api/dashboard/recent   — последние действия
GET  /api/dashboard/status-breakdown — разбивка по статусам
